# Rust ed25519-dalek 3 and rand 0.10 upgrade

## Which dependencies changed and why

The Rust workspace upgrades the direct dependencies `ed25519-dalek` from
2.2.0 to 3.0.0 and `rand` from 0.8.6 to 0.10.2 for #3355. These major
versions must move together so the signing and RNG APIs use compatible
`rand_core` traits. `rand` 0.10.2 is used rather than the newer 0.10.3
release to respect the repository's seven-day cooling-off policy.

The lockfile resolves the following package changes:

| Crate | Before | After |
|---|---|---|
| `ed25519-dalek` | 2.2.0 | 3.0.0 |
| `rand` | 0.8.6 | 0.10.2 |
| `ed25519` | 2.2.3 | 3.0.0 |
| `curve25519-dalek` | 4.1.3 | 5.0.0 |
| `signature` | 2.2.0 | 3.0.0 |
| `fiat-crypto` | 0.2.9 | 0.3.0 |
| `chacha20` | not present | 0.10.2 |
| `rand_core` | 0.6.4 and 0.10.1 | 0.10.1 (0.6.4 removed) |
| `rand_chacha` | 0.3.1 | removed |
| `ppv-lite86` | 0.2.21 | removed |
| `base64ct` | 1.8.3 | removed |
| `const-oid` | 0.9.6 and 0.10.2 | 0.10.2 (0.9.6 removed) |
| `der` | 0.7.10 | removed |
| `pkcs8` | 0.10.2 | removed |
| `spki` | 0.7.3 | removed |

The lockfile contains 348 packages before this update and 341 after it.
The old `rand` backend packages are replaced by `chacha20`; the older
Ed25519 PKCS#8 dependency chain is no longer required by the selected
`ed25519-dalek` features.

Key material continues to use the operating system entropy source. Since
rand 0.10 exposes `SysRng` as a fallible RNG, the code wraps it with
`UnwrapErr` for Ed25519 signing keys and the AES-256-GCM vault key. The
thread-local generator remains for nonces and identifiers: `rand::rng()` is
used for nonces, while `rand::random()` is used for generated IDs and the
attestation challenge.

## Security advisory relevance

This compatibility upgrade does not target a specific CVE or advisory.
The repository's dependency-review check reported no new vulnerability or
license findings for the dependency changes. This audit does not claim that
unmodified packages elsewhere in the dependency graph have no advisories.

## Breaking change risk assessment

The direct dependencies have major-version changes, so their RNG imports,
traits, and distribution module names require source updates. The workspace
continues to sign and verify with Ed25519, and the public identity and
signature formats are unchanged. Tests cover distinct OS-generated signing
keys, signature round trips and cross-verification rejection, as well as
distinct non-zero vault keys.

`cargo check --workspace` and `cargo test --release --workspace` pass for
the Rust workspace after the migration.
