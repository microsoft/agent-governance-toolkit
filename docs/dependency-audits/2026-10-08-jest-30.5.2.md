# Jest 30.5.2 update for the SDK and Copilot extension

## Which dependencies changed and why

Replacement for Dependabot PR #4118, original head
`8868504e4c39edf4d43cb8c77fc02083121aab7f`. Both
`agent-governance-typescript` and
`agent-governance-python/agent-os/extensions/copilot` update the exact Jest
development dependency from `30.4.2` to `30.5.2`. No other direct dependencies
change. Jest's matching internal packages, new file watcher, resolver,
source-map implementation, and transitive dependency graph change with it.
Official release notes:
`https://github.com/jestjs/jest/releases/tag/v30.5.2`.

The original merge-base and current main have identical manifests and
lockfiles for both packages. The reviewed original public-registry lockfiles
were regenerated with
`npm install --package-lock-only --ignore-scripts --legacy-peer-deps --offline --no-audit --no-fund`.
This preserved canonical registry URLs and upstream integrity metadata,
without discarding independent changes on main. Offline regeneration
establishes graph consistency, not independent registry verification.

Pre-install metadata review through the configured Microsoft mirror covered
all 123 changed package/version candidates. Each release was at least seven
days old; the youngest was approximately 8.37 days old at review. Jest
`30.5.2` was published on `2026-09-18T13:58:07Z`. The draft replacement's
hosted supply-chain run `37857591940` independently passed the seven-day
cooling-off and upstream lockfile integrity checks on its initial head.
Local canonical-registry checks failed closed on TLS handshake failures;
mirror metadata was not represented as an independent gate result.

## Security advisory relevance

No known advisory addressed. This is a development-tool update, not a
security fix or a claim that the dependency tree is vulnerability-free.

**The update remains blocked on an install-script policy decision.**
`jest-resolve@30.5.1` requires `unrs-resolver@^1.12.1`, replacing `^1.7.11`.
The SDK's existing resolver `1.11.1` is incompatible, so its regenerated
graph selects `1.12.2`. Both eligible `1.12.1` and `1.12.2` declare
`postinstall: node postinstall.js`. The Copilot lock already contains
`1.12.2`, but its presence is not evidence of security approval.

The tagged and installed resolver postinstall delegates to
`napi-postinstall@0.3.4` through
`checkAndPreparePackage(packageJson, true)`. Source inspection shows that
the helper checks platform bindings and can install or download a missing
binding. Source reference:
`https://github.com/unrs/unrs-resolver/blob/v1.12.2/napi/postinstall.js`.
The postinstall was not executed. Maintainers must review this lifecycle
behavior and decide whether a separately scoped policy change is justified
or the update should be deferred.

The new `@parcel/watcher@2.6.0` declares an installation hook and is already
on the repository's existing allowlist. Its inspected hook builds only when
`npm_config_build_from_source` is explicitly true. No new exception,
incompatible override, scanner modification, feed setting, or TLS setting
was introduced. Shared candidate-cap fix #4151 is already merged; both the
original audit and the replacement's hosted audit use `--max-deps 2000`
and fail specifically on the SDK resolver postinstall.

## Breaking change risk assessment

Jest 30.5 changes module resolution, file crawling, watching, and source-map
handling. Neither package needed application or configuration changes.
Both clean installations used
`npm ci --ignore-scripts --legacy-peer-deps --no-audit --no-fund`; platform
bindings were available without running lifecycle scripts.

On Windows with Node `26.7.0` and npm `12.0.2`, both packages passed
`npm run build`, `npm test -- --runInBand --no-watchman`, and `npm run lint`,
all with exit code 0. Pretest typechecking also passed. The SDK passed 692
tests across 41 suites; the Copilot extension passed 13 tests across two
suites. Disabling Watchman exercises Jest's new crawler. The SDK emitted an
advisory asynchronous-open-handle warning but exited successfully; this
record does not claim to diagnose or fix that warning.

The initial hosted Node `20.20.2` SDK run failed one existing circuit-breaker
test because its real five-millisecond reset deadline expired between
assertions. A controlled ten-millisecond scheduling delay reproduced the
same assertion failure on both current-main Jest `30.4.2` and updated
Jest `30.5.2`, confirming fixture timing sensitivity rather than changed
production behavior. The fixture now uses a scoped fake clock, restores real
timers afterward, preserves every original state assertion, and additionally
checks that execution is blocked at four milliseconds and allowed exactly
at five milliseconds.

On checksum-verified official Node `20.20.2`, the corrected fixture passes
even with the same scheduling delay. Both package builds, pretest
typechecks, full suites using `npm test -- --maxWorkers=2 --no-watchman`,
and lint pass with exit code 0. The SDK still reports an advisory worker
teardown warning while exiting successfully. No production behavior or
supported Node version was changed; hosted verification on the corrected
head remains required.

Hosted CI and human review remain necessary. Passing compatibility checks
does not approve the install script or make the draft merge-ready. GitHub
Copilot performed this user-authorized investigation and validation;
the specific output still requires human review.
